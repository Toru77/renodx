## 0. Decisions fixed here (the implementer makes none)

1. Two worst presents, one struct: `worst_present` = largest `frame_ms` of the run (the hitch the player feels); `worst_unattributed_present` = largest raw unattributed (`PerfTotalsValue::unattr_raw`, so a run whose clamped value is always 0 still names a present). The tab shows only the frame one.
2. Every value comes from `PerfTabSample::value[]` (the output of `MakePerfSample`: cumulative rows are already deltas against `prev`, with the counter-reset rule; non-cumulative rows `mesh_capture`, `pool_drain_excl_capture`, `pool_hooks`, `deform_hook_cpu` are the `*_frame_us` of the sampled present; Gpu rows are NaN when not measured). Never read `PerfCounters` (cumulative) for a spike. Since `SamplePerfPresent` moved the exchanges, all rows are one window with the frame interval, so `series.blocks[*][i]` pairs with `frame_ms[i]`.
3. Settings are NOT added to `cpu_total` and not to each other. Their rows are disjoint from each other; `follow_scan` is a Subset inside the `pool_drain_excl_capture` row, which is why the file says so in `basis`. `resolve_indirect` contains a GPU wait (wait_idle): its sum is an upper bound of the CPU cost of Scan indirect, not a pure CPU number.
4. No estimates (the earlier plan's `tlas_alpha_instances` / `tlas_wind_instances` gauges and ratio estimates are dropped: they would be labelled guesses). Exact wind sway cost is A/B only. Foliage motion has NO live part; `tlas_refit` and `refit_phase_0` are written as `context_rows` (their averages, not summed, they are shared with other work).
5. The inclusion switches go in a new `PerfInclusion` (`std::array<bool, 7>` plus `kPerfInclusionNames`), NOT in `CacheSwitches`: extending `CacheSwitches` would change the cache dump and break the literal checks `test_live.cpp:1452,1454`.
