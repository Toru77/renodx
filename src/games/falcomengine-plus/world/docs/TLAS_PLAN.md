## B. Decisions fixed by this plan (implementer must not change)

- Step 0 changes no pool or TLAS behaviour. Only new fields are `WorldInstance::tlas_entry_frame` (never hashed or dumped) and diag counters.
- Skip cadence: a skip never resets the 8-present snapshot cadence for the next real rebuild beyond what HEAD does (HEAD: rebuild at F, next at F+8). A skip at F sets `tlas_check_frame = F`; the gate uses `max(tlas_frame, tlas_check_frame)`. Without it a skip would make the next bump snapshot every present (8x cost). Latency for any new object is therefore never worse than HEAD.
- No delay on new objects anywhere. Nothing waits for a batch; the 8-present gate is unchanged. Per-present application is a follow-up decided by Step 0 phase numbers.
- "Equal" for a skip = static prefix byte-identical (descriptor memcmp + same id) AND dynamic suffix identical in identity (id, dynamic, wind, header x/y/z). Dynamic poses are left to the existing refit; `tlas_dynamic_revision` is NOT advanced by a skip (so the refit still runs).
- Never skip: reasons "first build", "refit quality", "refit failed"; empty snapshot; `!tlas_built`; `tlas_refit_failed`.
- The in-region Admit bump (Step 1b) is NOT implemented (trade in Step 1). Slack (Step 2) is session-only, default OFF, never saved.
- Step 2 spares live only in the STATIC block; any change to the dynamic block (add/remove/promote/wind flag) is "structural" and falls back to a full rebuild.

## Step 2: slack TLAS (zero added latency, default OFF)

Layout (one concept: a HOLE = instance slot with `id == 0`, parked leaf, `active[slot] = 0xFFFFFFFF`)
- Slots `[0,N_s)` real static, `[N_s, N_s+S)` static holes (S = `max(256, N_s/8)`, only when `N_s >= 1024`, else S = 0), `[N_s+S, cap)` dynamic. `cap = N_s + S + N_d`. `tlas_dynamic_first = N_s + S` (the existing `count_if(!dynamic)` at `:827-828` counts holes as non-dynamic when they are inserted before the dynamic block), so `RefitLiveTlas` (`:944-1048`, `df..end`) never sees a hole and needs no change. `data->active_count` = live count (cap minus holes), `stats.tlas_instances` too.
- Leaves/nodes: `N_s + S + N_d` leaves, `2*(that)-1` nodes (shader and `ValidateBvh` `bvh_build.hpp:256` both require it). Hole leaf = degenerate point box at an anchor, `prim = slot`. Spare anchors = centres of every `N_s/S`-th static real leaf (so after `SortBvhLeaves` the spare is Morton-adjacent to a real leaf and lies inside that leaf's parent bounds: never extends a parent, essentially never hit). Parked leaf anchor = centre of the removed instance's bounds. Descriptor of a hole is zeroed; `tlas_info[slot]` is a default `LiveTlasInstance` (`id 0`).
- Leaf prims in `RebuildLiveTlas` are assigned in the filter loop (`:773`); when S > 0, insert holes at `dynamic_first`, add S to every `prim >= dynamic_first`, append S hole leaves, then continue the HEAD path (`SortBvhLeaves`, `leaf_of` sized `cap`, build, validate, create). Active buffer: identity for live, sentinel for holes (`:842-844`). With S = 0 every line is the HEAD path (byte-identical).

No framework changes (`src/utils`, `src/mods`, CMake). No shader change. No single-use helpers (`LiveSnapshotMatchesTlas` has three users; `TryApplyLiveTlasSlack` is the one new non-trivial function because it is a deliberate unit with its own test). Switches are session-only. Do not edit the pinned fingerprint constant; if it moves, the change is wrong (or only the rebuild/skip split moved, which is already hashed as a sum).
