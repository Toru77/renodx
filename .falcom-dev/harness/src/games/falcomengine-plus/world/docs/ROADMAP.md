## Problems (ranked)
1. Admission gated on research verdicts; 46 families with VS SRV mask 0xB000 (t12/t13/t15, no t0) had zero SRV snapshots in all 90 captures — 33% of weighted tris (wall, buildings, ground, 5/6 terrain, distant mountain). Root cause inside capture unexplained (see T1).
2. Depth probe too loose: tol = max(5%·z, 0.002) in reversed-Z device depth; passing captures median z 0.00075. Offsets 8/28/56/76 and CB b5 "verified"; only 11/44 recipes at offset 0.
3. Pool snapshot capped at 1 MB (6,553 instances) vs 150,000-instance buffer: 10,889 beyond-snapshot skips, 449 copy drops.
4. No lifetime: mesh key = VB/IB handles + input layout; destroy_resource ignored; instances never evicted.
5. Stalls: every readback flush+wait_idle; pool staging mapped same frame.
6. BVH build serial, full rebuild per revision; float offsets (exact to 2^24).
7. Duplicated contract logic (raster VS struct copies; row-dot convention in 5+ functions).
8. Consumers lack UV/normal/material/alpha; skinned and foliage excluded.

## Decisions proposed
1. Admit by contract (InstanceContract C++ + HLSL; reflection-based VS classifier), research becomes validator.
2. Exact per-draw t15/b1 slice copies, 3-deep staging ring, no waits.
3. Pool lifetime: mesh identity without input layout, destroy_resource invalidation, scene epoch, static vs moving via world vs prevWorld, frustum eviction.
4. Geometry via create-time initial data shadow copy if available, else async readback.
5. CPU binned-SAH BLAS on worker; TLAS per active-set change; uint descriptors.
6. Consumers in OnBeforeLightingShaderDraw beside GTVBAO, new registers from t37, behind injection flags.
7. Separate lean runtime feed from research census; one gate function `RtAvailable()`.

## Round 9 result and round 10, 2026-10-06: game camera near fade
- Round 9 evidence (inspect + two dumps): the stray plane (instance of mesh uid 118, VS 0xE35C18B9 sighting, mesh captured from a main-pass indirect draw of VS 0x153708C7, same draw key) is a real object: no map change, no game writes to its VB/IB, 0 retirements, continuously seen. Its mesh is a pole plus an isolated 6.2 x 3.95 m horizontal quad at 3.66 m. Ruled out for this occurrence: survivors of a previous map (I) and in-place buffer rewrites (A).
- Cause found in the decompiled game shaders: every map-object PS that reads `disableMapObjNearFade_g` (e.g. 0x2F107485, 0x5F527E52, 0x533C1853; 13 of the 30 dumped PS bytecodes) discards with `fade = max(disableMapObjNearFade_g, min(1, (|camera - p| - param.x) * param.y)) * mapColor_g.w`, `alpha = opacity_g * color.w`, discard if `fade * alpha < dither4x4` (pattern flipped when param.z > 0); InstanceParam.color @96, param @128; cb_scene c25.w / c47 (same in the lighting PS 0xCA3D8596). ## GPU cost of the BVH debug views (2026-10-07)
- User reports ~22 ms GPU for the trace view (round 8: 17.2 ms). The trace is a DX11 compute software tracer, one primary ray per pixel at full resolution, and it is written for validation, not speed: binary Morton LBVH (lower quality than SAH), one triangle per leaf, test-on-pop traversal (one node fetched and box-tested per step instead of both children from the parent), no near-child-first ordering for closest hit, two 64-entry per-thread stacks in local memory (TLAS + BLAS), four dependent loads per triangle (node -> leaf -> 3 indices -> 3 vertices), bounds/validation checks and per-ray counters on every step, 192-byte instance records. A tuned software tracer (SAH or binned SAH, wide/compressed nodes, child ordering, precomputed triangle arrays, short stack or stackless) is typically several times faster.
- RT effects will not use this shape: shadow/AO rays are any-hit with short t_max, can run at half or quarter resolution with temporal accumulation and denoising, and only trace where the game shows geometry. Optimization belongs to M8/M13 after the BVH contents are steady.
